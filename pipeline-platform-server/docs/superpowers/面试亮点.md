# 面试亮点积累(随任务更新)

> 用途:写简历/准备面试时,从这里取材统合。每完成一个任务,同步补一节。
> 用法:每个技术点配「一句话亮点」+「面试官可能问什么、怎么答」。

## Task 1 环境准备

- **技术点**:Python 3.12 + uv(现代 Python 包管理,替代 pip/venv 一步到位)、Docker 跑 pgvector、SSH 隧道
- **一句话**:数据库只监听 127.0.0.1 不暴露公网,开发机通过 SSH 隧道 + 密钥免密访问 —— 安全习惯
- **问答**:「数据库为什么连 127.0.0.1?」→ 最小暴露面:不监听公网、无密码登录(密钥)、SSH 隧道加密通道

## Task 4 切片(chunking)

- **技术点**:LangChain 两段式切片(MarkdownHeaderTextSplitter 管结构 → RecursiveCharacterTextSplitter 管长度)、中文自定义分隔符、标题进 metadata 面包屑(section)、重叠窗口、短节合并限同一 h2
- **一句话**:标题当元数据带进每块,检索命中时能告诉大模型「这段来自简历哪一节」
- **问答**:「怎么切块?」→ 结构 + 长度两段式;800 字上限、100 字重叠;中文标点要自己加(库默认只有英文标点)

## Task 5 入库与检索

- **技术点**:pgvector 双写双表(豆包 1024 维 / 智谱 2048 维,一表一模型)、embedding 提供方注册表、HNSW 向量索引(vector_cosine_ops)、自动降级
- **一句话**:两个 embedding 模型各存一张表,主提供方故障自动降级;「查不到」不算故障不降级
- **问答**:「为什么双写?」→ 单模型单点故障风险;维度不同所以分表。「为什么 HNSW?」→ 近似最近邻,大数据量下比全表扫快几个量级,个人项目用它是提前养成正确习惯

## Task 5.5 混合检索(两路召回 + RRF)

- **技术点**:pg_trgm 三元组、GIN 倒排索引、word_similarity(短问长文打分)、RRF 排名融合、两路召回
- **一句话**:向量管「意思像不像」,关键词管「字面有没有」,RRF 只比排名不比分数
- **问答**:见下方「面试高频问答」前 4 条 —— 全是这个任务的内容

## Task 6 LangGraph Agent(工具调用循环)

- **技术点**:状态/节点/边/条件边、`create_react_agent` 库版本、`bind_tools` 工具声明、工具返回 `Command` 写状态、`InjectedToolCallId`
- **一句话**:「LLM 决定调工具 → 执行 → 把结果还给 LLM 再答」的循环就是 Agent 区别于普通聊天机器人的本质;来源收集靠状态扩展(sources 字段)+ 工具返回 Command 写进去
- **踩坑(面试加分项,真实经历)**:langgraph 1.2 的 create_react_agent 强制要求状态带 `remaining_steps`,但 ①TypedDict 默认值不生效,缺失从 0 起步 ②配 `operator.sub` 会把输入也过一遍运算,越传越负 ③`"add_messages"` 字符串注解已失效要传函数 ④0 步时其内部「空 tool_calls 判空为真」bug 会把正常回答替换成 Sorry。解法:薄壳包装,把库的坑关在模块里 —— 「用库不迷信库,最小用例先验证」
- **问答**:「create_react_agent 内部做了什么?」→ 见 graph.py 底部注释的手写三节点版,一层层能讲出来

## 面试高频问答(边做边攒)

1. **问:纯向量检索有什么缺点?** 答:对缩写/专有名词不敏感 —— 向量算语义相似,「bdms」这种词的字面信息被稀释,会命中语义像但无关的块
2. **问:怎么解决?** 答:混合检索:加一条 pg_trgm 关键词路做字面匹配,两路召回用 RRF 融合
3. **问:RRF 是什么?为什么不用加权求和?** 答:Reciprocal Rank Fusion,按排名融合(1/(60+rank) 求和)。两路的分数不是一个尺子没法直接加,排名可以
4. **问:word_similarity 和 similarity 的区别?** 答:分母不同 —— similarity 用长文本当分母,短问长文永远趋近 0;word_similarity 用查询词当分母,衡量「查询词在块里出现几成」
5. **问:pg_trgm 和 GIN 索引是干什么的?** 答:pg_trgm 把文本切成连续三元组;GIN 是倒排索引(词 → 出现位置),专门加速「哪些行包含某个值」这类查询,和 B+ 树是两种思路
6. **问:为什么数据库只监听 127.0.0.1?** 答:最小暴露面 + SSH 隧道访问,外网连 5432 都碰不到
